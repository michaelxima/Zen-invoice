# Changelog

## Unreleased — Phase 0 (safety net)

- **Database connections verify the server (step 1.5).** The app, the migrator, test-database setup and Drizzle Kit now share one TLS policy (`src/db/connection-options.ts`): a remote database is always reached with certificate and hostname verification, with the CA from `DATABASE_SSL_ROOT_CERT` or Node's public CA list; `sslmode=require/prefer/allow/disable/no-verify/verify-ca` in the URL is refused instead of silently overriding; only localhost/127.0.0.1/::1 may use plain TCP.
  Why: `ssl: "require"` made the postgres driver set `rejectUnauthorized = false`, so the connection was encrypted but anyone in the network path could impersonate the database. Verified by: unit tests plus driver-level tests against a test TLS server with a trusted, an untrusted and a wrong-host certificate (`src/db/connection-options.test.ts`) — pending local run.
- **Real sign-out and server-side sessions (step 1.2).** Every sign-in now creates an `auth_sessions` row and the session cookie is only accepted while that row is live, unrevoked and unexpired (30-day absolute lifetime). The sidebar's sign-out calls NextAuth `signOut` (it was a plain link to `/login`) and revokes the server-side session, so a copied cookie stops working at once; Settings has "Sign out of all devices". Google sign-in is off unless `GOOGLE_SIGNIN_ENABLED=1`; when on it binds Google's stable subject in `auth_accounts`, requires Google's `email_verified`, and refuses (never links) an email that already has an account. **Deploy note:** cookies issued before this change carry no session id, so every user is signed out once.
  Why: sign-out did not end the session, a stolen cookie stayed valid for 30 days, and Google login was matched to existing accounts by email alone, leaving the original password usable. Verified by: unit tests (`src/lib/auth/session-rules.test.ts`) and e2e (`tests/e2e/session.spec.ts`, updated `tests/e2e/proxy.spec.ts`) — pending local run.
- **Onboarding keeps what you type; shortcuts no longer eat text (step 1.3).** All onboarding fields are controlled state with the field component at module level (it was redefined on every render and saved values only on blur); Tab/Enter/mouse all submit current values; Back keeps them; the optional tax ID is validated and saved to `businesses.tax_id`; registration returns field errors instead of throwing, so production users see why it failed. Global `n` and `/` shortcuts now ignore inputs, textareas, selects, contenteditable, IME composition and modifier keys, run only on signed-in pages, and the Ctrl/Cmd+K "coming soon" alert was removed. Sign-up and sign-in rate limits are raised only for the browser-suite server (`E2E_DISPOSABLE_DB=1`, never in a production build) so the suite can register more than five accounts; the invoice e2e test now picks the app's alert instead of Next.js's route announcer.
  Why: the browser suite showed required values lost between steps, the tax ID was silently discarded, and typing `n` in a textarea navigated away. Verified by: unit tests (`src/lib/shortcuts.test.ts`, `src/lib/validations/onboarding.test.ts`) and e2e (`tests/e2e/onboarding.spec.ts`) — pending local run.
- **Disposable test database guard.** The browser suite, `db:seed` and `db:migrate:test` now refuse to run unless `TEST_DATABASE_URL` names a local `*_test` database that differs from `.env.local`; Playwright starts its own server on port 3105 with that database and never reuses a running one; `db:migrate` requires `MIGRATE_CONFIRM_DATABASE` for any other database; CI uses `invoice_claw_test`.
  Why: tests and migration experiments could previously write to the developer's everyday database. Verified by: unit tests in `src/db/disposable.test.ts` (pending local run).
- **WP-0.1** `.gitignore` now keeps `.env.example` and ignores Playwright output, `outputs/`, `.work/` (~75k files) and `.manus/`. Git repository still to be initialised (see MASTER-PLAN.md).
- **WP-0.2** Removed the unused in-memory `GlobalDataStore` plus stale copies `store.ts.new` / `store.ts.tmp` (older drafts that advertised payment methods the app doesn't support). DTO types moved to `src/lib/types/dto.ts`; 9 importers updated. Removed inline `console.assert` block from `calculator.ts`.
- **WP-0.3** Replaced the hand-rolled assert script with Vitest (`test:unit`, `test:watch`, `test:coverage`). Existing checks ported 1:1, plus edge cases (empty invoice, non-finite / non-positive amounts, half-up rounding). Vitest only collects `src/**/*.test.ts`, so Playwright specs in `/tests` are untouched.
- Verified by: pending local run of `npm run lint && npm run typecheck && npm run test:unit && npm run build`.
